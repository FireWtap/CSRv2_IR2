# E7 · Cached retrieval pilot

The merged pilot searches the eight MTEB retrieval test tasks using the
shared FP32 embeddings from E1 and E6b. The manifest keeps test queries and
all corpus rows in task order, including repeated texts across tasks.
The expected corpus size is 240,884 rows.

## Prepare and check the manifest

Run from the repository root on the Snellius login node.

```bash
source jobs/snellius/env.sh
uv run --frozen python scripts/prepare_e7_corpus.py \
  --output /scratch-shared/scur0911/csrv2/e7-inputs/retrieval8.jsonl
```

Before submitting, verify that the exact cache files exist and match the
expected NumPy shapes and dtypes. This opens memory maps and reads their headers.

```bash
uv run --frozen python - <<'PY'
from pathlib import Path

from csrv2_repro.common import load_config, upstream_prompts
from csrv2_repro.e7_profiling import cached_chunks, load_rows

cfg = load_config("configs/E7_retrieval8_cached_pilot.toml")
rows = load_rows(cfg)
assert sum(row["role"] == "document" for row in rows) == 240_884
count = sum(1 for _ in cached_chunks(cfg, rows, upstream_prompts(), Path(cfg["cache_root"])))
print(f"Verified {count} cache files")
PY
```

## Run search

```bash
mkdir -p outputs/slurm
sbatch --time=00:30:00 jobs/snellius/E7_profiling.job \
  search configs/E7_retrieval8_cached_pilot.toml
```

The config identifies the manifest and the source of its embeddings.
With `embedding_source = "cache"`, E7 resolves cache keys using the original
MTEB task inputs and gathers the manifest rows in the same order for both
models. With `embedding_source = "encoded"`, E7 reads arrays from a preceding
`encode` run on the same manifest and with the same model settings.

Each of the eleven cases searches all corpus blocks for each batch of 512
queries and returns the exact top 10. The benchmark uses 100 warm-up and
2,000 measured rounds per case, matching the paper's round counts and query
batch size. E7 uses blocks of 16,384 documents. The timed region covers
scoring and top-k selection. It starts after vector preparation.

## Inspect results

Open `results/E7/retrieval8_cached_pilot/retrieval_cache.json` for the timings,
throughput, corpus bytes and peak CUDA allocation. The JSON records the
manifest and cache paths. Slurm logs are in `outputs/slurm/`. Copy completed
results to shared scratch following D-009.

The [notebook](../../notebooks/e7_results.ipynb) reads the merged search JSON
and the separate SciFact encoding smoke JSON from job 29104915. On the
login node, use an existing Python kernel with pandas and Matplotlib.
For local Jupyter, run
`uv run --frozen --with jupyterlab --with matplotlib jupyter lab`.

The encoding breakdown reports wall time, throughput, and CUDA intervals
around the backbone call and the SAE. The search memory peak covers the
PyTorch allocator during a warmed batch with vectors already on device.
`corpus_bytes` counts the stored corpus representation. Divide mean batch
latency by batch size for amortized ms/query.
