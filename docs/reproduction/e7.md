# E7 · Encoding and exact retrieval timing

E7 separates encoding from search. The SciFact test pilot uses the released Qwen3-based
CSRv2 checkpoint and the dense Qwen3 baseline, both in fp32 with the upstream prompts on
queries and documents. It checks the implementation before a larger corpus is selected.

## Snellius

From the repository root, create the Slurm log directory before submitting a job.
The cache source and artifact destination can be configured independently.

```bash
mkdir -p outputs/slurm
sbatch jobs/snellius/E7_profiling.job search configs/E7_scifact_pilot.toml \
  cache /scratch-shared/scur0933/csrv2
```

This example uses personal scratch for runtime caches and the profiler trace. It reads
the shared embedding files without changing them. The last argument is passed as
`--cache-root`, so Slurm does not need to propagate a cache environment variable.
Python logs the resolved cache path before loading the dataset. For the timed encoding run, set
`SCRATCH_ROOT=/scratch-shared/scur0933/csrv2` on an account that can write there,
or obtain write permission for the shared output directory first:

```bash
export SCRATCH_ROOT=/scratch-shared/scur0933/csrv2
sbatch jobs/snellius/E7_profiling.job encode configs/E7_scifact_pilot.toml
# After encode succeeds:
sbatch jobs/snellius/E7_profiling.job search configs/E7_scifact_pilot.toml encoded
```

With no `SCRATCH_ROOT`, a local run uses `outputs/`. The Python entry point is
`uv run --frozen python -m csrv2_repro.e7_profiling`, followed by the subcommand and
`--config`. CPU runs are suitable for development checks. Use a new `run_name` to
repeat encoding.

## Inputs and artifacts

- `search --source cache` reconstructs the ordered MTEB inputs and opens only the
  cache chunks whose names match the exact texts, prompt and model tag. A missing
  chunk is an error. The command can run with the sparse head alone.
- `encode` accepts either the MTEB task and split in the config or an ordered UTF-8
  JSONL manifest set with `manifest = "/path/to/inputs.jsonl"`. Each row contains
  `id`, `text`, `role` (`query` or `document`) and `task` (an upstream prompt key).
  The order within each role determines the matrix rows. Use the same prompt settings
  for both models. Keep IDs unique within each role and task.
- New pre-head vectors, the ordered manifest and model metadata go to
  `$SCRATCH_ROOT/e7/<run_name>/`. The four arrays are float32 NumPy files under
  `embeddings/`. Use `search --source encoded` with the same inputs and model settings.
- Timing and provenance JSON files go to `results/E7/<run_name>/`. Slurm logs go to
  `outputs/slurm/`. The separate CUDA trace goes to
  `$SCRATCH_ROOT/e7/traces/<run_name>/<source>.json`.

## Timer boundaries

Encoding includes tokenization, backbone forward and, for CSRv2, the sparse head at
`encoding_k`. It excludes model loading, warm-up, device-to-host transfer of the saved
vectors and writing them to disk. Results separate documents and queries. MRL slices
the saved Qwen vectors, so it shares the baseline's backbone pass.

Search uses exact cosine on already prepared device-resident vectors. The timed
region includes scoring each corpus block and merging the top 10. The dense and MRL
paths use matrix multiplication. The CSRv2 path uses `torch.sparse.mm` with a CSR
corpus and dense queries. Search verifies its sparse scores and top results against
a dense reference before timing. Ties at the cutoff can select different valid IDs.

The SciFact pilot uses batch 32, 20 warm-ups and 100 timed rounds. Batches cycle in
input order and wrap to keep batch size fixed. The paper's large workload can use
512/100/2000 through the config. The authors do not specify the exact 1M-document
manifest or kernel, so a larger run must record the chosen manifest and GPU backend.
